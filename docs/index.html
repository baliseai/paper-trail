Paper Trail

150 work questions over 9,832 enterprise documents: agreements, contracts, audits, policies, technical reports and scans.

Most document benchmarks hand the model a few clean passages. “List every agreement up for renewal next quarter” needs every matching file out of thousands, scans and misfiled copies included.

Paper Trail scores the whole stack that answers it and names each part: the content system, the harness, the model.

What moves the score

Same library, same questions, one layer changed at a time. 103-question baseline.

  • Adding an index moved the same assistant, on the same files, by 25.7 and 83.5 points.
  • Swapping the model moved the score by up to 23.3 points across 8 models, and 4.9 across the top three.
  • Swapping the harness moved it 1.5 points when both shared a model and an index.

One run per question, so a point or two is a tie. The index in these runs is Vertesia’s: see funding and conflicts.

What the hard questions need

  • Every matching file, not the top few: counts, totals, renewals due.
  • One partner recognised under several legal names.
  • A contract followed across its modifications.
  • The page itself when the filename is wrong: signatures on files named Draft, expired agreements filed under Active/, renamed backups.

How to run it

  1. Load the 9,832 raw files in their folder tree with scripts/download_documents.py. Leave out nothing and add nothing.
  2. Ask each question as written, typos included. One run, no follow-up, no human help.
  3. Answer from the library. Web search and outside knowledge do not count.
  4. Treat today as 23 November 2026.
  5. Stop each run at 10 minutes. Record the time, and tokens if your system reports them.
  6. The system classifies, reads and indexes the files itself. A person may define document types and fields beforehand, but not from the questions, and may not tag or correct documents by hand, one at a time or in bulk.

How answers are graded

Correct1Says what the documents say. Counts and totals within about 10% count as correct; printed amounts in the files are the reference.
Partial0.5Finds the right documents and points the right way, but leaves something out or misses a key figure by more than 10%.
Wrong0States something the documents contradict, or names the wrong document.
No answer0Gives up, asks a clarifying question, times out, or says nothing is there when something is.

Baseline: one grader checked each answer against the documents, and a second graded the non-obvious ones blind. The Strict score also takes a point off for each wrong answer.

Run it on your system

1 · Build the library

python scripts/download_documents.py --out ./library fetches the 9,832 files from nasa.gov (about 11 GB) and checks each hash. Load them into your content system.

2 · Ask the 150 questions

scripts/run_custom.py runs them through your code or any program, with the time limit and checkpoints. scripts/grade_open.py scores your 25 open answers against the published ones.

3 · Send your answers

Email the file to benchmarks@baliseresearch.com, not a pull request: answers posted in public would reveal the held-out set. Only your grades are published.
